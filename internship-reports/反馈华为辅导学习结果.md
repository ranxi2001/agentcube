# 华为辅导学习计划与结果反馈

## 整体目标

以 AgentCube 和 Karmada 双项目为实战载体，培养具备跨项目技术视野和多社区协作能力的复合型开源工程师。不仅能独立交付特性，还能站在系统全局视角思考项目间的协同演进方向。

  ---
  第一阶段：双线入门

  AgentCube 线
  - 本地部署，跑通 CodeInterpreter demo，理解核心架构
  - 通读设计文档，掌握 Session、WarmPool 等关键模块

  Karmada 线
  - 本地搭建多集群环境（Kind），跑通 Deployment 跨集群分发
  - 通读 核心概念 (https://karmada.io/docs/v1.3/core-concepts/concepts/)：PropagationPolicy、ResourceBinding、Scheduler
  - 理解 Karmada 控制面架构（APIServer → Scheduler → Executor）

  开源技能
  - Git 工作流规范、Commit Message 规范、PR 流程
  - 两个项目的 Issue/PR 模板差异、Review 风格对比

  产出：各提交一个 PR（可以是文档修复或小 bug fix）

  ---
  第二阶段：AgentCube 维护 + Karmada 上手

  AgentCube 线
  - 认领 good first issue，独立完成修复
  - 补充单元测试和 E2E 测试
  - 参与当前版本稳定性维护

  Karmada 线
  - 认领 Karmada 的 good first issue，适应更大规模代码库的导航方式
  - 学习 Karmada 的多集群测试框架（集群注册、故障注入等）
  - 深入理解一个核心流程（如调度链路或资源绑定流程），能画出时序图

  开源技能
  - Code Review：学习在两个不同风格的社区做 Review
  - 技术写作：Issue 描述规范、PR 描述模板

  产出：AgentCube 完成 2-3 个 Issue；Karmada 完成 1-2 个 Issue 并输出一个核心流程的时序图

  ---
  第三阶段：双线特性开发

  AgentCube 线
  - 独立完成一个中等规模特性（如 WarmPool 策略增强）
  - 编写 Design Doc 并接受社区 Review

  Karmada 线
  - 参与一个特性的开发（如调度策略增强、FederatedHPA 扩展等）
  - 学习 Karmada 的 Proposal 流程和 SIG 机制
  - 参与 Karmada 社区会议或 SIG 讨论

  开源技能
  - Design Doc / RFC 写作：问题定义、方案对比、接口设计、兼容性分析
  - 如何做技术 trade-off 分析
  - 跨项目上下文管理：时间分配、优先级判断

  产出：两个项目各完成一个特性的完整交付（设计 → 实现 → 测试 → 文档）

## 结果反馈（可直接填写）

> 字符数仅统计以下四段正文：包含段落空白共 1199 个字符，去除空白后 1086 个字符，均未超过 1300 字限制。

我已完成 AgentCube 源码、架构文档和核心流程学习，并在本地跑通 CodeInterpreter demo 以及 Session 创建、代码执行、删除链路。现在能够说明 Router 接收和转发请求，Workload Manager 编排 Session 与 Kubernetes 资源，agent-sandbox controller 管理 SandboxWarmPool、SandboxClaim 和 Sandbox，PicoD 在 Sandbox 内执行进程与文件操作，各模块通过 Kubernetes API 和状态存储协作。结合 Karmada 实践，我还学习了资源从 Binding、Scheduler、Work 到成员集群的多集群交付过程，并绘制系统位置图梳理两个项目的控制面职责。

在模块开发方面，我完成 AgentCube agent-sandbox v0.4.6 兼容和 MCP Python SDK v2 迁移，两项改动均已合入；通过真实 E2E 验证 Session 创建、预热、删除与清理；完成 `WarmPoolAvailable` 功能实现、版本迁移和测试，当前 PR 仍在等待维护者审核。CI 与交付方面，我完成 branch push validation、release 版本处理、Dependabot 和 runner 固定等工作，并通过测量定位多架构构建瓶颈，将构建时间从 1610 秒降到 331 秒，约减少 79.4%。

在缺陷修复和版本验证方面，我独立验证 agent-sandbox v0.5.2/v0.5.3 的 API、对象接管、删除、GC、预热池补充和 conversion webhook，完成 unit、race、build、codegen 和 focused E2E。参与 SandboxPool、对象 ownership、运行时终止和指标设计 Review 时，我重点检查状态由谁写入、同名对象替换、失败后资源清理以及 CI 是否真正执行目标测试。同样的方法也用于 Karmada 的 cleanup、事件触发和多组件调度工作，帮助我理解大型 Kubernetes 项目中的跨组件状态交付。

截至统计日期，我在 AgentCube 和 Karmada 两个主仓创建 26 个 PR，其中 18 个已合入、7 个仍开放、1 个验证 PR 已关闭未合入；创建 6 个项目 Issue，并完成至少 16 个可定位的实质 PR Review。在导师反馈下，我学会先说明任务要解决什么问题和产生什么结果，再补必要证据；一个 PR 只承担一件边界清楚的事情；使用 Agent 辅助开发时，要从现有接口、调用方、测试和维护者要求多方确认防御性代码是否必要，避免在假想风险上增加无用逻辑。后续将继续加强真实环境验证并推进开放任务收敛。
